# 리스크 관리 계획

## 10.1 식별된 리스크 및 대응 방안
1. **그누보드7 생태계 성숙도**: G7은 비교적 새로운 아키텍처이므로 서드파티 모듈 호환성 이슈 발생 가능.
   - *대응*: 코어 수정을 절대 금지하고, 모든 커스터마이징은 독립 플러그인으로 격리하여 G7 코어 업데이트 시 충돌 방지.
2. **신선 식품(꽃) 배송 리스크**: 배송 지연 또는 상품 손상 시 고객 불만.
   - *대응*: 주문 시 "배송 지정일" 외 "배송자 안내 문자" 자동 발송 기능 강화, 관리자 대시보드에 이상 징후(지연 등) 알림 설정.
3. **테넌시 확장 시 성능 저하**: 단일 DB에 `tenant_id`가 추가되면 인덱스 효율이 떨어질 수 있음.
   - *대응*: 초기에는 단일 테넌트로 안정화 후, 트래픽 증가 시 `stancl/tenancy`의 Multi-Database 모드로 전환할 수 있도록 레포지토리 패턴을 추상화하여 구현.
4. **자본 제약**: 마스터님의 자본 없는 시작 조건을 고려하여, 초기에는 라즈베리파이나 저비용 VPS + 오픈소스 스택으로 구축하고, 수익 발생 시 클라우드 인프라로 마이그레이션하는 단계적 접근 채택 [[8]], [[9]].
